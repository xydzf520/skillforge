# 企业 AI 能力如何积累与演进

整体产品与实现边界见[能力地图](CAPABILITIES.md)；完整数据流与训练图见[数据与训练专题](DATA_AND_TRAINING.md#training)。本页侧重核心资产结构。

从角色和业务交接理解系统时，先阅读[企业运行图解](OPERATING_MODEL.md)：组织协作、业务交付、Harness 调用和改进决策；这些图将建议运行方式与当前实现状态分开标注。

## 为企业设计什么

企业业务由目标、流程、组织权限、数据源和审批约束共同决定。SkillForge 将这些约束纳入技能生命周期：需求先转为技能合同与版本，再绑定工具和节点，经过测试、审核后发布。平台管理控制流程，执行节点承担运行任务。

`app/agent_core/graph.py` 定义两条 LangGraph：保存路径负责意图解析与技能生成；发布路径增加风险检查、适配器绑定、沙箱执行、发布门禁和跨模型检查。`runtime.py` 使用持久化检查点与中断恢复接口，人工确认是流程的一部分。

## 积累什么

| 资产层 | 积累内容 | 代码证据 |
|---|---|---|
| 业务能力 | Skill 定义、输入输出合同、工具绑定、版本和发布记录 | `app/skills/core/models.py`、`app/skills/asset_models.py`、`app/skills/lifecycle/` |
| 执行经验 | 执行步骤、决策日志、运行产物、失败与人工反馈 | `app/execution/models.py` |
| 可检索知识 | 文档、分块、索引任务和查询记录 | `app/knowledge/models.py` |
| 学习资产 | 来源事件、提取产物、跨对象关联、审核状态、改进候选 | `app/learning/models.py`、`app/learning/service.py` |
| 训练资产 | 样本、来源、数据集版本、任务、评估与部署版本 | `app/training/models.py` |

`LearningEvent → LearningArtifact → LearningFlowEdge` 连接来源、产物和下游对象。知识、样本或建议可以追溯到来源事件，而不是只有一份无法解释来历的回答。

## 训练什么

持续改进有三条路径，只有第三条涉及模型参数训练：

1. **流程与技能改进**：根据执行结果提出 Skill、工具调用或 Agent 配置的改进候选，经确认后修改资产。
2. **知识与记忆积累**：将经过权限、质量与敏感性处理的资料用于检索和上下文复用，不改变模型权重。
3. **模型训练控制**：整理样本与数据集版本，创建训练任务，向已配置节点派发，收集评估，再审核部署或回滚。`TrainingJob` 默认类型包含 LoRA，具体执行能力由训练网关与节点决定。

收集数据不代表模型已训练。公开版关闭默认自动审核、训练与部署开关，节点地址须显式配置。没有训练任务、评估与部署记录时，不应宣称“企业专属模型已训练成功”。

## 最终形成什么

目标是建立可复用的企业 AI 能力库：业务人员用技能和项目完成工作，产品团队通过真实反馈优化流程，技术团队能定位失败、回溯版本并控制发布。持续积累业务流程资产、可复用工具、组织知识和有来源的训练样本。

这套结构为持续优化提供基础。实际效率、模型质量、使用覆盖率或收入变化需要业务测量，不能由代码规模或测试通过推导。

## 系统边界

- Web：Vue 3、Arco Design、Vite；流程编辑器使用 React / React Flow。
- 服务：FastAPI、SQLAlchemy、PostgreSQL、Redis、GitPython。
- Agent：LangGraph 状态图与检查点；CLI/MCP/Bridge 是协作接口，不捆绑闭源运行工具。
- 节点：`bridge/skillforgebridge.py`，具体技能与训练能力由授权节点提供。
- 协作：组织权限、审核、任务、项目、知识和素材工作台。
- 隔离：公开源码、部署凭据、Skill 资产仓库、业务运行数据分别管理。

## 自建 Harness 与业务交付层

平台内的 AgentCore、Playbook 与执行服务分别承担生成／检查编排、技能组合及节点调度。外部自建 Harness 可以通过 Project SDK/API 和 MCP 连接授权能力；兼容节点通过 Bridge 接收版本和配置并回报运行。适配需要核对身份、输入输出、版本、超时、取消及结果含义。

业务交付还涉及项目应用宿主、个人声明式界面、报告收件箱、人工待办、审批和素材评审。生成结果到真实业务完成之间需要负责人确认与结果核实。知识、提示词、Skill 和私有模型的更新也应分别验证，不能将同一“完成”状态复用于所有生命周期。

提示词注册器、用量跟踪、数据治理和优化器提供管理基础。其中提示词默认选择目前为进程内状态；优化器有模拟回退及共享候选文件问题；跨模型检查可以跳过。这些事实及完成标准记录在[实现限制](CAPABILITIES.md)，不属于本次已修复功能。
