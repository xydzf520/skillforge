项目希望解决的核心问题是：**一个人借助 AI 完成工作以后，如何把有效方法交给团队，并通过实际结果持续改进？**

本案例的个人职责依据本人陈述。产品实现、个人贡献与业务成果分别核对；代码不能单独证明贡献比例或经营收益。

## 1. 从业务需求确定产品范围

围绕企业日常使用，产品需要同时满足四类需求：

- **员工能用**：有明确的使用入口、输入要求、输出标准和例外处理方式。
- **业务负责人能验收**：能检查结论依据、确认动作并核实实际结果。
- **产品与研发团队能维护**：业务规则、提示词、工具和版本能够修改、验证与交接。
- **管理者能评估投入**：质量、人工复核、维护成本和团队复用有可检查的依据。

由此组织“业务标准 → Skill 或应用 → 审核与授权执行 → 人工核实 → 反馈改进”的产品流程。先交付可验收的业务能力，再根据真实反馈决定扩展范围。[查看组织与交付图](OPERATING_MODEL.md)

## 2. 关键方案与取舍

以下按当前产品结构归纳，供结合具体版本讨论；不作为完整的历史决策日志。

| 要解决的问题 | 设计选择 | 价值与代价 |
|---|---|---|
| 方法如何跨人员复用 | 用 Skill、输入输出约定、案例和版本承载业务方法 | 便于复用与交接，也需要持续维护规则和案例 |
| 多种运行环境如何协作 | 平台管理权限、资产、审核和观测；Harness 与兼容节点承担具体执行 | 业务方法与运行方式可以分别演进；接入仍需适配和回归 |
| 多应用和多节点如何统筹 | 统一能力网关组织模型、工具及数据调用，队列、调度器与 Bridge 协同分布式执行 | 复用集成与运行管理，保留额度、权限和执行依据；高可用及通用跨实例路由仍需验证 |
| 生成结果如何成为业务交付 | 报告、待办、负责人确认和实际结果分别记录 | 明确责任与完成依据；人工复核时间需要计入成本 |
| 反馈应该用于哪类改进 | 区分知识更新、提示词／流程调整与模型训练 | 按问题选择投入，避免在样本与评价不足时直接进入训练 |
| 强模型和私有小模型如何选择 | 按复杂探索与稳定任务，比较质量、延迟和全成本 | 保留模型选择空间，不预设小模型必然更便宜或更准确 |

这组设计体现的产品关注点是：业务优先级、角色交接、能力复用、执行边界和效果验证。实现限制与待完成项见[能力地图](CAPABILITIES.md)。

## 4. 用一条业务故事演示

以合成的“经营异常分析”为例，建议按以下顺序讲解：

| 环节 | 需要讲清楚的判断 | 可展示内容 |
|---|---|---|
| 定义目标 | 哪些异常值得处理，由谁验收 | 合成输入、指标口径、正反例与输出标准 |
| 组织能力 | 如何让其他成员复用方法 | 已配置的手动／复用路径、Skill 版本和输入输出约定 |
| 授权执行 | 谁可以在什么环境运行哪个版本 | 审核、权限、节点配置与运行记录 |
| 交付核实 | 报告如何交给负责人，并核实后续动作 | 报告、待办、确认或拒绝、实际结果或未知状态 |
| 迭代改进 | 失败应修数据、流程还是模型 | 来源反馈、改进候选、测试案例与下一版验证 |

这是演示路线，不是已配置好的企业场景。演示前核对[创建路径](../spec/skill-creation-paths.md)与运行环境；未接通的步骤用图解说明，合成数据明确标注。旧编程运行时已移除，自动文件生成、自建 Harness 适配及真实训练不能被当作已验收演示。

## 5. AI 辅助研发如何体现个人能力

有说服力的表达应覆盖完整工作方法：**定义问题与验收 → 准备上下文和约束 → 与 AI 编程工具协作实现 → 检查差异与测试 → 部署验证 → 修正问题**。

每个实际案例应说明人负责什么判断、AI 完成什么工作、如何发现并修正错误，并对应设计、差异、测试或部署材料。具体工具名称是研发方式的补充；平台提供 CLI／MCP／SDK 接口，不代表某位作者使用了所有工具或独立完成全部代码。

开发时使用 AI 编程工具，与产品运行时接入 Harness 是两件事。前者展示研发协作，后者需要具体运行能力和验收证据。

## 6. 与简历衔接的项目表述

> 负责 SkillForge 企业 AI 平台规划与交付，推进“统一管控、分布式执行”的产品架构，通过统一能力网关统筹模型、工具和业务数据调用，协同多节点任务执行；将权限、版本审核、调用额度与执行追踪纳入运行管理，连接业务交付、反馈沉淀和训练评估流程，为跨应用能力复用及企业自有模型优化提供基础。

简历中的个人优势侧重“将业务需求转化为平台能力、统筹技术与业务交付”的通用能力；网关、队列与节点协作放在项目经历中作为证据。没有独立测量时，不写“高可用集群已落地”“高并发性能领先”或具体降本比例。

在个人简历中，可在这段职责与方案之后另列获准使用的业务成果，写清统计范围、时间和口径。实际训练、业务采用、效率改善和公开准备状态分别陈述。
