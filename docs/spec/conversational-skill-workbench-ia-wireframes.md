# 对话式 Skill 工作台页面原型与信息架构

## 1. 设计目标

页面设计需要同时服务两类人：

- 小白用户：先把完整 Skill 做出来
- 专业用户：再进入结构化调优和工作流编排

因此信息架构必须支持“先简后深”：

1. 先通过对话形成结果
2. 再进入模块化编辑
3. 最后进入专业验证与编排

## 2. 信息架构总图

```text
顶部导航
├── Dashboard
├── Skills   ← 一级入口
├── Reviews
├── Playbooks
├── Executions
└── Admin

Skills
├── A. 生成入口
│   ├── 新建 Skill
│   ├── 从需求描述生成
│   └── 从已有 Skill / 模块引用生成
├── B. 工作台主页
│   ├── 对话区
│   ├── 模块导航
│   ├── 模块编辑区
│   ├── 变更预览区
│   └── 验证区
├── C. 工作流区
│   ├── 工作流预览
│   ├── 工作流画布
│   └── 节点级调优入口
└── D. 版本与回放区
    ├── 版本差异
    ├── 测试结果
    └── 历史回放
```

## 3. 页面清单

建议形成以下页面体系：

- `Skill 生成页`
- `Skill 工作台页`
- `Workflow 工作台页`
- `验证与回放页`
- `引用选择弹窗`
- `Patch 预览弹窗`

页面统一归属于顶部 `Skills` 导航域。

## 4. 页面一：Skill 生成页

## 4.1 页面目标

让小白用户通过自然语言生成完整 Skill 草稿。

## 4.2 页面结构

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部导航 > Skills > 新建 Skill                            │
├────────────────────────────────────────────────────────────┤
│ 对话生成 Skill                                            │
├────────────────────────────────────────────────────────────┤
│ 左：对话输入区                                            │
│ 右：当前生成结果摘要                                      │
│                                                            │
│ [输入你的需求...]                                          │
│                                                            │
│ 生成结果摘要：                                             │
│ - 目标                                                     │
│ - 规则数量                                                 │
│ - 参数数量                                                 │
│ - 输出表格字段数                                           │
│ - 测试样例数量                                             │
│                                                            │
│ [继续补充] [生成完整草稿] [进入专业模式]                   │
└────────────────────────────────────────────────────────────┘
```

## 4.3 核心交互

- 用户输入需求
- 系统返回简明摘要
- 用户确认后生成完整 Skill 草稿
- 可直接跳转到工作台页

## 5. 页面二：Skill 工作台页

## 5.1 页面目标

这是核心页面，既支持对话式定向修改，也支持专业化结构编辑。

## 5.2 页面布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ 顶部导航 > Skills > Skill 工作台 > 某个 Skill                     │
├────────────────────────────────────────────────────────────────────┤
│ Skill 工作台  [草稿/已验证/待审核]                                 │
├────────────────────────────────────────────────────────────────────┤
│ 左侧对话区 │ 中间模块区                     │ 右侧预览区           │
│            │                               │                      │
│ 用户输入    │ @目标                         │ 变更摘要             │
│ 系统回复    │ @规则                         │ diff 预览             │
│ 快捷建议    │ @参数                         │ before / after       │
│            │ @输出表格                     │                      │
│            │ @测试样例                     │                      │
│            │ @工作流                       │                      │
├────────────────────────────────────────────────────────────────────┤
│ 底部：验证区 / 历史回放 / 应用修改 / 放弃修改                      │
└────────────────────────────────────────────────────────────────────┘
```

## 5.3 三栏职责

### 左栏：对话区

功能：

- 输入自然语言修改意图
- 系统给出模块定位建议
- 系统给出 patch 摘要

### 中栏：模块区

功能：

- 展示模块导航
- 支持切换到专业编辑视图
- 显示当前模块状态

### 右栏：预览区

功能：

- 展示 patch 摘要
- 展示模块级 diff
- 展示应用前后对比

## 5.4 模块导航设计

建议每个模块显示：

- 模块名称
- 状态标记
- 是否有未应用 patch
- 最近一次验证结果

示例：

```text
@目标        已生成
@规则        已修改未验证
@参数        已验证
@输出表格    待完善
@测试样例    验证失败
@工作流      草稿
```

## 5.5 专业编辑形态

### `@目标`

- 文本块编辑

### `@规则`

- 规则步骤列表
- 条件分支编辑
- 条件说明和动作编辑

### `@参数`

- 参数表格
- 参数说明
- 默认值
- 影响说明

### `@输出表格`

- 列结构表格
- 字段格式选择
- 接收对象设置

### `@测试样例`

- 样例输入输出表
- 断言列表

### `@工作流`

- 轻量节点预览
- 工作流草稿列表
- 跳转到 Workflow 工作台

## 6. 页面三：Workflow 工作台页

## 6.1 页面目标

用于专业用户进行工作流节点和连线层面的调整。

## 6.2 页面结构

```text
┌────────────────────────────────────────────────────────────┐
│ 顶部导航 > Skills > Skill 工作台 > 工作流                  │
├────────────────────────────────────────────────────────────┤
│ Workflow 工作台                                           │
├────────────────────────────────────────────────────────────┤
│ 左侧：节点列表 / 引用来源                                 │
│ 中间：画布                                                 │
│ 右侧：选中节点或边的属性编辑                               │
├────────────────────────────────────────────────────────────┤
│ 底部：workflow patch 预览 / 结构验证 / 应用               │
└────────────────────────────────────────────────────────────┘
```

## 6.3 节点级调优入口

每个节点都应支持：

- 查看关联 Skill
- 跳回 Skill 工作台
- 只调该节点的 `@参数`
- 只调该节点的 `@输出表格`
- 只调该节点的 `@规则`

## 7. 页面四：验证与回放页

## 7.1 页面目标

让专业用户深入理解 patch 的影响。

## 7.2 页面结构

```text
┌────────────────────────────────────────────────────────────┐
│ 验证与回放                                                │
├────────────────────────────────────────────────────────────┤
│ Tab1: 结构验证                                             │
│ Tab2: 测试样例                                             │
│ Tab3: 历史回放                                             │
│ Tab4: 影响总结                                             │
└────────────────────────────────────────────────────────────┘
```

## 7.3 必须展示的信息

- 通过了什么
- 失败了什么
- 变好了什么
- 变差了什么
- 风险点是什么

## 8. 关键弹窗与浮层

## 8.1 引用选择器

用途：

- 选择引用哪个 Skill
- 选择引用哪个模块

结构：

```text
选择来源 Skill
选择来源模块
选择引用策略
- 完全参考结构
- 仅参考格式
- 仅参考流程
```

## 8.2 Patch 预览弹窗

用途：

- 应用前最终确认

内容：

- 这次改了哪个模块
- 主要变化
- 验证结果摘要
- 风险提醒

## 9. 典型用户流程

## 9.1 小白用户流程

```text
进入生成页
→ 输入需求
→ 系统生成完整草稿
→ 查看摘要
→ 保存
→ 可选进入工作台继续优化
```

## 9.2 专业用户局部调优流程

```text
进入 Skill 工作台
→ 对话输入问题
→ 系统定位到某模块
→ 生成 patch
→ 看 diff
→ 跑验证
→ 应用
```

## 9.3 工作流编排流程

```text
进入 Workflow 工作台
→ 增删节点或调整边
→ 生成 workflow patch
→ 做结构验证
→ 应用
```

## 10. 角色化界面策略

## 10.1 小白视图

界面原则：

- 少字段
- 少技术词
- 默认显示对话和摘要
- 隐藏复杂编辑器

主要入口：

- 顶部导航 `Skills`
- 生成 Skill
- 继续补充
- 应用建议

## 10.2 专业视图

界面原则：

- 强调模块导航
- 强调 diff 与验证
- 可直接编辑结构
- 可进工作流画布

## 10.3 审核视图

界面原则：

- 只看变化点
- 只看风险摘要
- 快速通过/驳回

## 11. 页面状态定义

每个页面要考虑以下状态：

- 初始空状态
- 加载中
- 已有草稿
- patch 生成中
- patch 已生成待验证
- 验证中
- 验证完成
- 应用成功
- 应用失败

## 12. 设计约束

### 约束一

默认不允许同时编辑多个模块。

### 约束二

默认不允许跳过验证直接应用 AI patch。

### 约束三

工作流编排页不承担“生成完整 Skill”的职责。

### 约束四

对话区不能替代结构编辑区。

## 13. 一句话总结

页面原型要体现的不是“聊天变多强”，而是：

`让用户先用对话做出来，再在结构化工作台里把它调好。`
