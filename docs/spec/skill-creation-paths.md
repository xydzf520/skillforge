# Skill 创建路径与可用边界

核对日期：2026-09-20。适用于当前公开准备版；路由存在不表示外部服务已配置或完整流程已验收。

## 选择入口

| 起点 | 路径与入口 | 前提与当前限制 |
|---|---|---|
| 已有 Skill，希望修改定义、代码或参数 | `/skills/:id`，手动编辑、验证和保存 | 需要编辑权限与独立 Skill Git 仓库；保存不等于发布 |
| 已有可复用能力或模板 | `/hall` 内按当前权限查找、复用或派生 | 需要已有资产；`/skills/templates` 当前重定向到 `/hall`，不是独立模板库 |
| 只有业务描述，需要澄清需求 | `/skills/new` 的需求采访与骨架合成 | Architect / Swarm 使用普通模型调用路径，需配置模型；生成骨架不等于完整代码已测试可运行 |
| 希望 AI 读写完整文件并执行工具 | Workbench 编程对话、运行时驱动的生成任务 | **不可用**：旧编程运行时已移除，替代 Harness 尚未接入验收 |
| 有外部 Skill 文件或受控仓库 | 管理员的数据／Git 导入工具 | 先核对格式、来源、权限和冲突；导入不自动赋予发布权限 |
| 希望从节点收回 Skill | 节点管理中的相关入口 | 需要该节点在线、协议兼容和当前账号授权；逐节点验收 |

旧文档中的星级质量和“几秒生成”没有公开版基准证据，已移除。耗时取决于任务、模型、工具和审核，实际运行结果需单独记录。

## 推荐的第一次演示

1. 在测试环境准备一个合成 Skill 或有权复用的模板；先确认当前账号可编辑。
2. 手动核对 `SKILL.md`、输入输出合同、工具范围与测试，保存到独立 Skill Git。
3. 使用合成输入运行验证；外部模型、数据源和执行节点尚未配置时，明确标记未验证步骤。
4. 检查变更与测试结果，再提交人工审核；不要把草稿保存或模型输出当作发布成功。

需求采访、Swarm 骨架合成与编程 Harness 是不同路径，不能因一条路径返回结果就声称其他路径已恢复。
