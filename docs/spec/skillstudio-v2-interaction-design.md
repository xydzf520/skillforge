# Skill Studio v2 — 交互设计方案

> **阅读范围**：本文保留原项目的设计与版本演进记录，不作为公开准备版的安装或验收指南。正文中的“当前／已完成／已上线”须结合当时版本理解；现行可用范围见[能力地图](../public/CAPABILITIES.md)，实测范围见[验证记录](../public/VALIDATION.md)。规范性权限与审核要求不因该说明而放宽。


> **版本**: v1.0 | **日期**: 2026-04-06 | **状态**: 方案评审
>
> 基于 Codex 深度分析 + 用户实测反馈，重新设计 Skill 新建和编辑的交互体验。

---

## 核心理念

**不是"6个模块表单"，而是一个统一画布。**

Skill 编辑器应该让用户同时看到：业务目标 → 决策逻辑 → 参数 → 测试结果。
AI 不是右侧聊天框，而是嵌在编辑过程中的结构化共编助手。

## 1. 新建 Skill：从业务问题启动

### 1.1 入口页

不做传统 4 步向导。页面只有一个大输入框：

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   描述你想让 Skill 替你做什么判断/流程                        │
│   例如：根据 ROI 和预算消耗速度，判断是否加预算/降价/暂停     │
│                                                             │
│   支持粘贴 SOP、会议纪要、现有规则、接口文档                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘

  [从业务问题开始]   [从模板开始]   [导入 SKILL.md]
```

**模板不按行业分类，而按 Skill 类型**：
- `阈值决策型` — 如 EC-投放-01（ROI/预算判断）
- `多阶段流程型` — 如 waoowaoo-studio（分镜→图片→视频）
- `分类路由型` — 如客服意图分类
- `外部 API 工作流型` — 如数据拉取→处理→推送
- `审批决策型` — 如风控审批链

### 1.2 Blueprint 生成

用户输入需求后，AI 生成 **Skill Blueprint**（不是长文本，是 6 张结构卡）：

```
┌──────────┐ ┌──────────┐ ┌──────────┐
│  目标     │ │ 建议输入  │ │ 建议输出  │
│ 一句话   │ │ ROI数据   │ │ 绿/黄/红  │
│          │ │ 预算数据   │ │ 动作建议  │
└──────────┘ └──────────┘ └──────────┘
┌──────────┐ ┌──────────┐ ┌──────────────┐
│ 规则骨架  │ │ 候选参数  │ │ 待确认问题    │
│ Step 1-3 │ │ 盈亏线    │ │ 盈亏线固定？  │
│          │ │ 绿灯系数  │ │ 消耗看日/时？ │
└──────────┘ └──────────┘ └──────────────┘
```

**待确认问题**只问缺失项，用户改完后点「生成骨架」→ 进入正式编辑器，初始就带上规则、参数、输出、测试、反例。

### 1.3 创建模式自动选择

- 输入描述偏"判断/决策" → 默认 `Decision Canvas`（决策型画布）
- 输入描述偏"流程/阶段/步骤" → 默认 `Stage Flow`（流程型画布）

## 2. 编辑 Skill：一个画布，五个区域

### 2.1 页面布局

```
┌─ 状态栏 ──────────────────────────────────────────────────────┐
│ SkillName [draft] │ v1.2 │ 编辑|源码 │ 覆盖率 85% │ 保存 发布 │
├──────────┬────────────────────────────┬───────────────────────┤
│ 业务上下文│    中央规则画布             │   检查器/AI           │
│          │                            │                       │
│ 目标     │  ┌─────┐    ┌─────┐       │ [当前选中节点]        │
│ 输入源   │  │Step1│───→│Step2│       │ 条件: ROI > {{1.2}}   │
│ 输出字段 │  │检查ROI│   │检查预算│    │ 结论: 绿灯            │
│ 风险等级 │  └──┬──┘    └──┬──┘       │ 动作: 加预算          │
│ 覆盖率   │     │绿/黄/红  │充分/不足  │                       │
│ 最近失败 │     ▼          ▼          │ [补全相反分支]         │
│          │  ┌─────┐                  │ [提取为参数]           │
│          │  │最终  │                  │ [生成边界测试]         │
│          │  │输出  │                  │ [解释给业务]           │
├──────────┴──┴─────┴──────────────────┴───────────────────────┤
│ 测试工作台: 回归用例 │ 临时模拟 │ 反例 │ 变更影响              │
└───────────────────────────────────────────────────────────────┘
```

### 2.2 中央规则画布（Decision Canvas）

**不是表单，而是可视化决策树/流程图**：

- 每个 Step 是一个可折叠分组节点
- 每条分支显示为 `条件 → 结论 → 动作` 三段卡片
- 连线展示执行路径
- 顶部有 mini-map 和覆盖率标记

**两种透视切换**（同一数据，不同视图）：
- `Canvas`：看整体逻辑和流向（默认）
- `Decision Table`：高密度规则表格（适合阈值多的 Skill）

### 2.3 参数和规则联动

参数不单独躺在另一个模块，而是规则里的一级元素：

- 规则条件中引用参数时显示为 **参数 chip**：`ROI > {{roi_green_ratio: 1.2}}`
- Chip 上直接显示当前值
- Hover 时高亮所有引用处
- 点击 chip 弹出浮层：可直接改值、看影响范围、命中用例

**修改参数时的实时反馈**：
```
把 roi_green_ratio 从 1.2 改到 1.15
  → 画布中所有相关条件高亮
  → 底部只重跑受影响用例
  → 提示：7 个样本从黄灯变为绿灯
  → AI 自动补一个边界反例
```

### 2.4 节点编辑（右侧检查器）

点击画布中任一节点，右侧显示该节点的专属编辑器：

```
┌─ Step 1: 检查 ROI ──────────────────┐
│                                      │
│ 条件表达式: ROI > 盈亏线 × {{1.2}}   │
│ 依赖输入:   ROI 数据, 盈亏线         │
│ 引用参数:   roi_green_ratio          │
│ 动作:       推荐加预算               │
│ 命中测试:   3/5 通过                 │
│                                      │
│ ─── AI 动作 ─────────────────────── │
│ [补全相反分支]  [提取为参数]          │
│ [生成边界测试]  [生成反例]            │
│ [解释给业务]    [修复失败用例]         │
└──────────────────────────────────────┘
```

### 2.5 插入新节点

在任意节点按 `/` 或点击 `+`，选择：
- `判断节点` — if-then 分支
- `动作节点` — 执行操作
- `API 调用` — 调外部接口
- `人工审批` — 等待审批
- `返回结果` — 输出结论

## 3. 测试工作台（常驻底部）

### 3.1 四种测试模式

| Tab | 功能 |
|-----|------|
| **回归用例** | SKILL.md 里定义的测试，每次编辑后自动跑受影响的 |
| **临时模拟** | 手动输入参数试跑 |
| **反例** | 容易误判的场景，失败时阻止发布 |
| **变更影响** | 改了参数/规则后，最近 N 天历史数据重放对比 |

### 3.2 测试和画布联动

- 点击任一测试行 → 中央画布**高亮该输入走过的路径**
- 失败节点标红
- 右侧显示 `期望输出 vs 实际输出` diff
- 用户不需要自己推理执行路径

### 3.3 覆盖率

- 每个节点显示分支覆盖率和边界覆盖率
- 缺少边界样本时，在节点上直接提示 `缺少边界测试`
- 改规则/参数后只自动重跑受影响用例
- 发布前必须全量回归

## 4. AI 角色：结构化共编，不是聊天

### 4.1 四个介入时机

| 时机 | AI 做什么 | 输出形式 |
|------|----------|---------|
| **创建时** | 从业务问题生成 Blueprint + 骨架 | 6 张结构卡 + 初始 Skill |
| **编辑时** | 在节点级别给 inline 建议 | 灰显补全（Tab 接受） |
| **测试失败时** | 分析失败原因，给修复 diff | 结构化 diff（接受/拒绝） |
| **发布前** | Lint + 冲突检查 + 业务影响审查 | 审批摘要 |

### 4.2 编辑时的 AI（像 Copilot）

- 用户写了 `ROI > 盈亏线 × 1.2 → 加预算`
- 系统灰显补出 `维持` 和 `降价/暂停` 分支
- 用户按 `Tab` 接受
- **不是去聊天框里问"帮我补全规则"**

### 4.3 节点级 AI 动作（短按钮，不是 prompt）

| 动作 | 说明 |
|------|------|
| `补全相反分支` | 当前条件的 else 分支 |
| `提取为参数` | 把 magic number 抽成可配参数 |
| `生成边界测试` | 围绕当前条件的边界值生成测试 |
| `生成反例` | 容易误判的场景 |
| `解释给业务` | 用非技术语言解释这条规则 |
| `修复失败用例` | 分析失败原因并给修复建议 |

### 4.4 发布前审批摘要（给业务负责人看）

```
本次改了 2 个阈值
42 条回归中 8 条输出变化
变化集中在 ROI 1.70-1.80 区间
无新增未覆盖分支
```

不展示规则细节，只展示影响。

## 5. 三种视图（同一页面，不跳转）

| 视图 | 适合谁 | 看到什么 |
|------|--------|---------|
| **编辑模式** | AI 工程师/AIBP | 完整画布 + 检查器 + 测试 |
| **讲解模式** | 业务负责人 | 简化流程图 + 自然语言说明 + 参数值 |
| **审批模式** | 审批人 | 变更 diff + 影响摘要 + 批准/驳回 |

### 5.1 个人图形化界面 overlay

图形化界面分两层：

- **Skill 默认界面**：属于 Skill 展示 contract，修改必须进入 Skill Git、验证、审核、发布链路。
- **个人界面 overlay**：属于 `user_id + skill_id + surface` 的个人偏好，只影响当前用户当前 Skill，不影响其他用户或其他 Skill。

AI 在这里不是“前端代码生成器”，而是受限的界面编排助手：

- 只能读取当前用户对当前 Skill 已授权可见的元数据、当前 commit、input/output contract、`param_ui_schema`、`result_ui_schema`、组件白名单、脱敏样例输出和当前个人 overlay。
- 只能输出声明式 UI schema / JSON Patch / overlay。
- 禁止生成或执行 Vue/JS/HTML/CSS，禁止新增数据源、MCP scope、Skill 逻辑、trigger、工作流、权限或发布态。
- 用户自定义提示词只保存为该 `user_id + skill_id + surface` 的个人默认提示词；AI key 只允许服务端统一 AI 封装从后台 `SystemConfig ai.*` 读取，个人 UI AI 不读取或写入 `.env`，不得进入前端响应、overlay、run trace 或执行参数。
- 用户执行 Skill 时必须把 `ui_pref_id`、`ui_pref_version`、`base_skill_commit`、`merged_ui_schema_hash` 和实际 `params` 写入提交记录和 run trace。

详细规格见 `docs/spec/skill-personalized-ui-overlay.md`。

## 6. 技术架构

### 6.1 数据模型：Skill AST（唯一事实源）

```js
SkillAST = {
  goal: string,
  inputs: DataInput[],
  outputs: OutputField[],
  params: Param[],          // 每个参数知道被哪些节点引用
  nodes: DecisionNode[],    // 决策/流程节点
  tests: TestCase[],
  counterExamples: CounterExample[],
  dataSources: DataSource[],
}

DecisionNode = {
  id, name, type,           // 'decision' | 'action' | 'api_call' | 'approval' | 'output'
  conditions: Condition[],  // 每个条件引用的参数自动追踪
  branches: Branch[],
  position: { x, y },      // 画布位置
}
```

SKILL.md、画布、参数表、测试面板都是 AST 的投影。

### 6.2 前端组件树

```
SkillStudio
├── StatusBar                   # 状态栏
├── ContextSidebar              # 左侧业务上下文
│   ├── GoalSummary
│   ├── InputList
│   ├── OutputList
│   ├── RiskBadge
│   └── CoverageIndicator
├── RuleCanvas                  # 中央画布
│   ├── CanvasView (SVG + dagre)
│   ├── DecisionTableView       # 切换
│   └── MonacoSourceView        # 切换
├── InspectorPanel              # 右侧检查器
│   ├── NodeEditor
│   ├── ParamChipEditor
│   └── AIActionBar
└── TestWorkbench               # 底部测试
    ├── RegressionTab
    ├── SimulationTab
    ├── CounterExampleTab
    └── ImpactTab
```

### 6.3 实现优先级

| 阶段 | 内容 |
|------|------|
| **v2.0** | Skill AST 模型 + 概览页改造 + Blueprint 创建流程 + AI 动作按钮（节点级） |
| **v2.1** | Decision Canvas（SVG + dagre 自动布局）替代表单编辑 + 参数 chip 联动 |
| **v2.2** | 测试工作台常驻 + 路径高亮 + 覆盖率 + 受影响用例自动重跑 |
| **v2.3** | AI inline 补全（灰显 + Tab 接受）+ 发布前审批摘要 |
| **v2.4** | Decision Table 视图 + 讲解模式 + 审批模式 |

## 附录：与 v1 对比

| 维度 | v1（当前） | v2（目标） |
|------|-----------|-----------|
| 新建 | 空白表单 / AI 生成一段文本 | 业务问题 → Blueprint → 骨架 |
| 编辑 | 6 个模块表单跳转 | 统一画布 + 检查器 + 参数 chip |
| 规则 | input 填条件/结论 | Decision Canvas 可视化 |
| 参数 | 单独模块，与规则无关 | 嵌在规则中的 chip，改值实时联动 |
| 测试 | 单独页面，手动触发 | 常驻底部，改完自动跑 |
| AI | 右侧聊天框 | 节点级动作按钮 + inline 补全 |
| 审批 | 看规则 diff | 看影响摘要 |
