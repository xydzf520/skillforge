# SkillForge

**简体中文** · [English](README.en.md) · [Apache-2.0](LICENSE) · [参与贡献](CONTRIBUTING.md) · [问题反馈](https://github.com/xydzf520/skillforge/issues)

**把分散的 AI 应用、工作方法和计算资源，变成团队可复用、可管理的业务能力。**

SkillForge 是一个可自行部署的**企业 AI 工作台与技能协作平台**。员工使用应用和技能完成工作；团队统一管理项目、方法、权限与版本；已接入的执行节点承担任务，运行结果与人工反馈为后续改进留下依据。

它面向存在重复建设、跨人交接或统一治理需求的团队。企业可以沿用已有开发工具、模型服务和自建 Agent 运行框架，逐步接入；实际收益需要对照现有做法验证。

## 为企业解决什么问题

| 企业需要 | SkillForge 如何承载 | 价值如何判断 |
|---|---|---|
| **统一管理个人与部门的应用** | Project 汇集轻量网页、看板和内部工具，记录负责人、部门、可见范围、版本及运行结果 | 同事能否找到、使用并接手，减少重复开发与失管应用 |
| **共享经过验证的工作方法** | Skill 将业务规则、提示词、工具和输入输出约定封装为有版本的能力；按权限发现、安装、改进和提交审核 | 非原作者能否复用同一方法，减少重新摸索与返工 |
| **让交付有依据、有责任人** | 组织权限、审核、运行记录、报告与待办连接建设、使用和人工确认 | 结果是否可复核，失败能否定位，业务动作是否真正完成 |
| **复用已有计算资源** | 能力网关、任务队列和 Bridge 节点连接已配置的模型与执行环境 | 是否减少排队、重复部署和新增资源投入；包含运维成本一起比较 |
| **积累可持续改进的资产** | 将结果、纠正与来源关联，整理为知识、Skill 改进候选及合格训练样本 | 下一次工作是否更可靠，改进能否在相同标准下被验证 |

Project 管理应用入口与运行，带独立后端的应用仍需自己的环境。Skill 共享包含方法和版本；目录中有一个条目，不等于它已被验证或广泛复用。[项目与共享能力详解](docs/public/PROJECTS_AND_INTEGRATION.md)。

## 企业如何使用

1. **明确任务与标准**：业务负责人说明输入、判断依据、输出、验收条件，以及需要人确认的动作。
2. **建设并复用方法**：团队编写 Skill、组合流程或接入 Project；先复用已有能力，再补齐缺口，测试后按对应流程审核和发布。
3. **交付给团队使用**：员工从网页打开应用；开发工具或自建 Harness 通过授权接口调用能力；需要节点的任务在已配置环境执行。
4. **核实结果并改进**：负责人确认、纠正或拒绝结果，记录例外；维护者据此更新知识、方法或模型，并验证下一版本。

**业务负责结果，能力维护者负责方法与版本，平台团队负责接入和运行。** 生成报告、发出通知、任务执行成功和业务完成分别记录。[组织协作与运行图解](docs/public/OPERATING_MODEL.md) · [Skill 编写指南](docs/guides/skill-authoring-best-practices.md)。

## 我们对未来的判断

**模型会继续进步，企业仍需要掌握自己的业务资产。** 工作流表达做事步骤，提示词表达目标与标准，Skill 封装可复用方法，关联结果与人工纠正的日志提供改进依据。资产的价值在于有效、可追溯和被复用，并需要权限、质量与保留期限管理。

**强模型与企业私有小模型可以分工。** 新任务、复杂问题可以借助强模型探索；高频、稳定且有合格样本的任务，可以评估私有小模型微调。企业可在基座许可允许的范围内私有部署并保留专有数据与微调产物。模型价格会变化，小模型也有算力和维护成本，应比较同一任务的质量、延迟与总成本。

**运行工具可以演进，经过验证的方法应尽量延续。** 开放接口与自建 Harness 为企业保留适配空间；更换模型或框架仍需测试。以上是产品方向，通用自动择模、持续收益和完整自动学习效果尚无生产验收结论。

## 网关：让企业闲置资源参与任务执行

**将公司已授权、已接入的闲置服务器和工作站资源，用于模型推理、小模型微调、生图等任务，是这套网关与节点体系的重要用途。** 目标是复用现有算力、减少重复部署和任务等待；是否更快、更省，取决于模型、硬件、传输与实际负载。

平台统一管理身份、能力入口、任务、版本和运行记录；Bridge 连接实际执行环境。已有资源信息包括在线状态、GPU、可用显存与部分队列信息，训练及部分媒体路径据此选择符合条件的节点。

| 任务 | 当前基础 | 接入条件 |
|---|---|---|
| **模型推理** | 模型配置、项目网关、常驻模型与训练模型推理接口 | 配置模型、推理运行时与授权；部分兼容通道仍绑定固定目标 |
| **小模型微调** | 样本与数据集版本、训练资源选择、LoRA / QLoRA 等训练任务、产物及评估回收 | 合格数据、兼容模型、显存／算力与训练运行器；审批后执行 |
| **生图及素材生成** | 生图能力／服务调用、素材任务与产物记录；部分媒体任务有基于能力、显存和队列的节点派发 | 生图需配置相应服务或运行器；将生图分配给自有闲置 GPU 的具体路径仍需适配与验收，不能以外部 API 成功替代 |

调用路径是 **应用／Agent → 授权网关 → 对应任务服务与可用执行环境 → 状态、产物及用量回传**。节点定时是主路径，平台保留补偿机制。这里的分布式协作由多个模块共同完成，尚未形成适配任意设备、全任务统一调度和跨实例故障切换都已验收的通用算力池。

[网关机制与边界](docs/guides/project-gateway-sdk.md#网关职责与分布式协作) · [节点部署](bridge/README.md)。

## 接入：开发工具、SDK 与自建 Harness

| 接入方式 | 用来做什么 |
|---|---|
| **Codex / Claude Code 与 `sf` 插件／CLI** | 在授权范围发现、安装和复用个人或部门 Skill，测试修改后提交审核；登记或上传 Project |
| **MCP** | 发现并调用平台已授权的工具与数据能力，复用接入方式 |
| **浏览器、Node / TypeScript、Python SDK** | 为网页、后端服务和 Agent 创建运行、记录输入、调用能力、回传报告与待办，并查询 trace |
| **企业自建 Harness** | 自行组织 Agent 的任务循环、上下文和工具执行，通过 SDK/API/MCP 接入平台；兼容执行节点通过 Bridge 接收配置和回传结果 |

Skill 复用的基本流程是 **发现 → 安装 → 使用与测试 → 修改后提交审核**。项目接入的基本流程是 **声明负责人和能力 → 验证入口 → 注册应用 → 按权限使用并回传结果**。共享对象是授权技能与能力入口，个人工具账号及上游密钥不随之共享。

先打通一条只读任务：项目授权 → 创建运行 → 调用一个能力 → 回传结果 → 核对记录。SDK 以仓库源码提供，模型、工具和运行器由部署者配置。[插件与共享指南](docs/guides/sf-codex-claude-workflow.md) · [SDK 与 Harness 详解](docs/public/PROJECTS_AND_INTEGRATION.md) · [合成项目示例](docs/examples/projects/README.md)。

## 数据与训练：从工作结果到下一版能力

**授权输入 → 按版本执行 → 输出、调用记录与人工纠正 → 去重、敏感性处理及质量审核 → 可复用资产。** 按问题选择三条改进路径：

| 改进什么 | 形成什么 | 怎样验证 |
|---|---|---|
| 数据与知识 | 有来源、范围与时效的知识 | 检索与事实是否准确 |
| 提示词、Skill 与工作流 | 经测试和审核的新版本 | 同一案例下的质量、复核成本与失败处理 |
| 模型能力 | 合格训练样本与独立评估集 | 数据集版本 → 审批 → 节点训练 → 原模型对照与业务评估 → 审核部署 → 观察／回滚 |

可训练的目标包括稳定的业务分类、信息提取、报告表达与工具使用；具体选择应由任务和样本决定。**有日志不等于有合格样本，训练完成不等于效果提高。** 失败和纠正需要标明用途，训练与评估应防止同源泄漏。

Skill 代码与版本保存在独立 Git 仓库；运行、来源关系和数据集元信息保存在数据库；文件与模型产物保存在配置的存储或节点。自动训练与部署审批默认关闭，但部分 Project 样本出口默认开启，首次接入前需分别确认采集、AI 分析、学习和出口范围。

[完整数据流、训练与部署流程](docs/public/DATA_AND_TRAINING.md) · [数据记录与出口配置](docs/guides/project-gateway-sdk.md#数据记录与训练出口)。

## 部署与开始评估

平台由 **Vue 工作台、FastAPI 服务、PostgreSQL、Redis、独立 Skill Git 仓库**组成；流程编辑器采用 React。节点、模型与文件存储按任务配置。

```bash
git clone https://github.com/xydzf520/skillforge.git
cd skillforge
```

1. **部署控制平台**：准备 Python 3.12、Node.js 22.22 或更新兼容版本、npm 11.13.0，初始化独立配置和数据库，构建网页并启动服务。完整命令见[本地部署指南](docs/public/GETTING_STARTED.md)，Docker 路径见[独立预览部署](deploy/preview/README.md)。管理员密码由部署者设置，没有通用初始密码。
2. **接入模型与执行资源**：配置组织权限、模型和必要工具；需要使用公司计算资源时安装并注册兼容 Bridge，核对节点能力、版本与任务回报。训练、推理和生图所需运行器分别配置。
3. **验证再扩大使用**：从合成数据和只读流程开始，核对输入、输出、权限与异常；引入真实业务前验证数据范围、停止行为及备份恢复，再由另一位成员使用和接手。

仅有一次性个人任务，或现有工具已经满足需求时，先评估增加平台是否值得。缺少数据授权、验收标准或维护负责人时，先补齐这些条件。

<a id="value-measurement"></a>

**试点看四项：交付质量、端到端耗时、团队复用、每个合格任务的总成本。** 成本包括建设、模型、算力、人工复核、返工和运维；释放工时先计为产能，不能直接当作财务收益。达不到预先约定的标准时，应调整或缩小采用范围。
